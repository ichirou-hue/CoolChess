# План развития фронтенда CoolChess

Документ описывает, в каком порядке развивать сайт ученика. Работа ведётся по одному этапу: сначала доводим текущий этап до понятного рабочего результата, затем переходим к следующему.

## Где мы сейчас

- **Каркас и вход** — React, Vite, TypeScript и Tailwind уже используются; страницы входа и регистрации есть. Нужно довести отображение состояния аккаунта и обработку ошибок.
- **Партия с ботом** — доска и ходы уже связаны с API. Нужны звуки, более ясные подсветки и аккуратное завершение партии.
- **Курсы и задачи** — задачи уже запрашиваются с сервера по тегу урока, а ход решения проверяется сервером. Нужна проверка на запущенном API и согласование полного продолжения решения.
- **Профиль** — подключены серверный рейтинг, опыт, число решённых задач и привязка Lichess. Баланс валюты и серия занятий пока не приходят в используемых ответах API.
- **Сообщество** — таблица лидеров подключена к API с фильтрами по рейтингу, уровню и задачам. Для живого онлайна, PvP, турниров и кланов нужны отдельные серверные функции.
- **Мобильная версия** — адаптивные стили уже есть, но каждый экран нужно отдельно проверить и поправить.

## Этапы

### 1. Каркас и вход в аккаунт

Довести регистрацию и вход до простого надёжного сценария: показать, вошёл ли ученик, дать выйти, ясно объяснять ошибки сервера и не терять экран при обновлении страницы. Проверить адрес API и поведение, когда сервер выключен.

**Готово, когда:** ученик может зарегистрироваться, войти, обновить страницу и увидеть своё состояние аккаунта; при ошибке он видит понятное сообщение.

### 2. Шахматная доска и партия

Довести доску `Chessground` и правила `chess.js`: легальные ходы, подсветка выбранной фигуры и возможных ходов, анимация, звуки, очередь хода, шах и результат партии. Сверить игру с серверными маршрутами:

- `GET /api/games/active`
- `POST /api/games/start`
- `POST /api/games/move`
- `POST /api/games/resign`

Ход должен обновлять позицию и на доске, и на сервере. Ошибка сервера не должна оставлять доску в ложной позиции.

**Готово, когда:** можно начать партию, делать только разрешённые ходы, обновить страницу и получить актуальное состояние партии, а затем увидеть её завершение.

### 3. Курсы и шахматные задачи

Сначала связать каждую задачу с её темой курса. Загружать задачи с сервера, отправлять решение туда же и после верного ответа обновлять прогресс. Закрытые или пройденные уровни показывать зелёным. Не давать ученику выбирать тему случайным ползунком внутри задачи — тема должна следовать из выбранного урока.

Из найденных серверных маршрутов для этого этапа:

- `GET /api/puzzles/random`
- `POST /api/puzzles/{id}/solve`

Перед подключением сверить с бэкендером, как сервер принимает ход решения и как передаётся тема. Если у API пока нет прогресса по урокам, сначала можно сохранять прогресс локально, но пометить это как временное.

**Готово, когда:** из урока открываются задачи именно по его теме; правильный ответ засчитывается, неправильный не засчитывается, а прогресс уровня сохраняется и отображается.

### 4. Профиль, магазин и статистика

Подключить профиль к серверным данным, затем показать рейтинг, XP, валюту, серию занятий и статистику задач. Подключить привязку Lichess, если ученик сам её начинает. Не хранить окончательные награды только в браузере: их должен подтверждать сервер.

Для магазина пока не найдено API каталога, покупок и инвентаря. Поэтому сначала можно подготовить экран, но настоящие покупки включать только после появления серверных маршрутов.

**Готово, когда:** профиль показывает серверные данные ученика; награда за задачу не теряется после обновления страницы; магазин не обещает покупку, которую сервер пока не умеет выполнить.

### 5. Сообщество, соревнования и турниры

Первым делом подключить таблицу лидеров к `GET /api/leaderboard?category=elo|level|puzzles`. Затем согласовать с бэкендером отдельные API для присутствия учеников онлайн, PvP-лобби, партий, турниров и кланов. Пока этих API нет, показывать эти части как макет или честную пометку «скоро», а не как работающую игру.

**Готово, когда:** таблица лидеров загружается с сервера, а соревновательные действия реально создают и обновляют серверные данные.

### 6. Адаптация и проверка экранов

После реализации каждого этапа проверять его на широком экране, планшете и телефоне: не обрезается ли доска, доступны ли кнопки, помещаются ли панели и можно ли управлять доской касанием. Исправлять найденные ошибки перед переходом к следующему экрану.

**Готово, когда:** основные сценарии доступны на всех трёх размерах экрана и нет известных блокирующих ошибок.

## Что делать следующим

Следующий шаг — **проверить подключённые задачи, рейтинг и профиль на запущенном сервере**, затем согласовать с бэкендером недостающие поля и ответы. Вход и партия уже используют реальные серверные маршруты.

## Важное про сервер и модель Maia

Фронтенд использует сервер через HTTP API и не должен содержать веса шахматной модели. Файл `backend/models/maia3-5m.pt` теперь находится там, где его ожидает сервер, и исключён из Git правилом `*.pt`.

## Что нужно согласовать с бэкендером

- Для задач API сейчас возвращает позицию, первый ход соперника и проверяет только первый ответ ученика. Для анимированного показа всей комбинации фронту нужна последовательность правильных ходов в ответе задачи или решения.
- API задач принимает один тег базы Lichess, а не ID урока. Поэтому каждому уроку нужен проверенный список подходящих тегов; старый тег `oneMove` в начальных уроках отдельно нужно заменить на реальные данные или согласовать специальную серверную подборку.
- В ответе профиля сейчас нет текущего баланса валюты и серии занятий. Награды за задачи приходят в ответе решения, но для постоянного баланса нужен профильный API с этими полями.
- Завершение теории и ежедневная серия пока не сохраняются на сервере. Нужен маршрут прогресса курса, если эти данные должны синхронизироваться между устройствами.
- Запрос на PvP, онлайн-статус, турниры, кланы и магазин остаётся отдельным серверным контрактом; в просмотренных API для них маршрутов нет.
