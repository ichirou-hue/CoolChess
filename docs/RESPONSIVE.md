# Адаптивный интерфейс CoolChess

Общий стиль, порядок действий и пропорции доски сохраняются на всех устройствах.
Количество колонок меняется по доступной ширине окна в **CSS-пикселях**. Физическое
разрешение монитора само по себе не определяет компоновку: масштаб Windows/macOS,
плотность экрана и zoom браузера меняют доступную ширину.

## Правила компоновки

Ограничения размеров собраны в `frontend/src/responsive.css`, который подключается
после визуальных стилей. При изменении адаптивности меняйте правила в этом файле.

| Доступная ширина | Компоновка |
| --- | --- |
| 320–480 px | Одна колонка, крупные карточки маршрута и действия PvP на всю ширину |
| 481–900 px | Доска и панели идут последовательно; карточки главной — в две колонки |
| 901–1100 px | Доска и настройки PvP/задач стоят рядом; история партии — под доской |
| От 1101 px | Каталог курса и основной урок рядом; сообщество — в две колонки |
| От 1280 px | Настройки, доска и история игры с Maia — в три колонки |
| До 1400 px включительно | Навигация открывается кнопкой меню |
| Более 1400 px | Навигация в шапке; содержимое ограничено шириной 1440 px |

- Основные кнопки имеют высоту минимум 48 px. На сенсорных устройствах минимум
  48 px применяется также к кнопкам меню, курса и другим действиям.
- Кнопка входа в PvP находится после текста в обычном потоке, поэтому переносы
  строк, другой шрифт и увеличение текста увеличивают карточку по высоте.
- Доски сохраняют квадратную форму и сжимаются внутри колонки. Короткое окно
  прокручивается по вертикали; высота игровой страницы не фиксируется.
- `svh` учитывает мобильные панели браузера; для браузеров без поддержки остаётся
  `vh`. Боковые отступы учитывают вырезы экрана через `safe-area-inset`.
- Размер текста полей ввода на телефоне — не меньше 16 px. Масштабирование
  страницы пользователем разрешено.
- Меню закрывается по выбору страницы, Escape и нажатию за пределами шапки.
  Escape возвращает фокус на кнопку. Внутри длинного меню доступна прокрутка.
- Анимации сокращаются при `prefers-reduced-motion`, а эффекты наведения не
  смещают кнопки на устройствах без hover.

## Разные ветки или ошибка вёрстки

Если каждый запускает свою копию, сначала выполните на обоих компьютерах:

```bash
git branch --show-current
git rev-parse HEAD
git status --short
```

Сравнивайте SHA коммита и локальные изменения: одинаковое имя ветки не гарантирует
одинаковые файлы, а разные ветки могут указывать на один коммит. Существующий
фикс `.pvp-auth-card` уже был в коммите `3884362` ветки `dev` до этой доработки.
В старой ветке он может отсутствовать. Перенесите нужные изменения обычным
merge/rebase/cherry-pick, сохранив незакоммиченные правки.

После синхронизации установите зависимости из актуального lockfile и перезапустите
frontend. Для статического размещения пересоберите `dist` и обновите HTML вместе
с assets. В браузере сравните масштаб, `window.innerWidth`, загрузку шрифтов и
сделайте перезагрузку без кеша. Если на одинаковых файлах при одинаковой ширине
наложение остаётся, это воспроизводимый дефект компоновки.

## Проверки

```bash
cd frontend
pnpm install --frozen-lockfile
pnpm exec playwright install chromium firefox webkit
pnpm run test:layout
pnpm run build
```

Тесты собирают production-версию и запускают отдельный preview на `127.0.0.1:4173`; backend и реальные аккаунты
не нужны. API подменяется тестовыми данными. Google Fonts отключены специально,
чтобы проверить устойчивость компоновки с системными шрифтами.

Проверяются десять основных маршрутов на одиннадцати размерах от 320×568 до
3840×2160, включая телефон в альбомной ориентации. Дополнительные сценарии:
вход в PvP с асинхронной загрузкой пользователя, длинный ник, длинный текст и
увеличенный шрифт, регистрация, открытие/закрытие меню, поворот
планшета без перезагрузки, выбор фигуры и ход двумя касаниями. Проверяется
выход текста/кнопок за экран, пересечение соседних панелей и квадратность доски.

Chromium, Firefox и WebKit проверяют три браузерных движка. WebKit в Playwright
не является полноценным Safari на iPhone/macOS, а Chromium — точной копией
Яндекс Браузера. Перед публичным выпуском дополнительно проверьте реальные
iPhone/iPad (Safari), Android (Chrome/Яндекс), macOS (Safari/Chrome), браузерный
zoom 125/150/200%, экранную клавиатуру и вырезы экрана. Проверки с обычными
загруженными веб-шрифтами также полезны.

Принципы: [адаптивный дизайн MDN](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/CSS_layout/Responsive_Design),
[media queries MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Media_queries/Using).
